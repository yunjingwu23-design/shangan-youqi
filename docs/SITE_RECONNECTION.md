# 主站重新接入

> 当前导航与功能地址已按四模块重组，以 [信息架构与导航文档](INFORMATION_ARCHITECTURE.md) 为准。下表保留前一轮接入范围；旧面经、Mock 和笔记 URL 继续兼容，账号及数据接口不变。

## 修复范围

原交付包包含一份 HTML 交互样品、Logo 和 PRD，不包含原站的 Next.js 后端。此前账号版错误地把 `/` 跳转至 `/login`，而已登录的 `/login` 又跳转到 `/workspace`，导致 Logo 也无法返回主站。本次用原生 Next.js 页面接回主站，不嵌入旧 HTML、不恢复假微信二维码或浏览器里的演示账号。

| 入口                  | 当前行为                                                                   |
| --------------------- | -------------------------------------------------------------------------- |
| `/`                   | 公开首页、四类招聘入口和各模块导航，登录后仍可浏览                         |
| `/jobs`、`/jobs/[id]` | 岗位搜索、模糊/精准模式、类型/城市/行业/届别筛选、JD 和一体化投递信息      |
| `/workspace`          | 保留现有账号、个人记录和 RLS，增加返回主站和功能编辑器的导航               |
| `/resume`             | 登录后分块编辑简历、模块排序、A4 预览、浏览器 PDF 导出、岗位版本和云端保存 |
| `/interviews`         | 面经中心与本站原创准备指南；不冒充真实企业面经或实时抓取                   |
| `/review`             | 手动复盘笔记、岗位关联、历史记录；AI 开关启用时连接既有录音复盘            |
| `/mock`               | 可保存的自主文字面试练习；真人 Mock 服务说明及未确认的预约意向             |
| `/admin/jobs`         | 登录且具备明确运营角色后可录入、保存草稿、核对来源、发布或下架岗位         |

直接登录默认进入工作台；从简历、岗位保存或其他模块进入登录时，`next` 只接受本站允许的页面，认证后回到原模块。外站、协议相对 URL、登录循环和 API 路径不能作为返回目标。

## 数据保留与实际能力

简历仍使用已有 `workspace_entries(kind=resume)`，不更换内部 user_id。旧纯文字草稿读取时转换为可编辑模块，不自动覆盖原记录；明确点击保存后才写入排版格式。简历保存校验 `updated_at`，旧标签页无法覆盖新版本。另存版本创建新记录；刷新通过 URL 中的简历 ID 重新载入。

文字模拟、手动复盘和 Mock 意向保存在现有 `interview_review` 类型记录中，继承已有账号权限和删除机制。工作台对这些记录显示可读摘要，并连接对应编辑页面，不显示内部 JSON 元数据。练习题是通用准备提示，没有自动 AI 评分或实时语音能力。

原样品的 4 个岗位仅用于交互预览；没有正式岗位时显示清晰的样品标识，不提供实际投递、未核验邮箱复制或写入正式投递记录。不会把原型里的公司名称当作正在招聘的事实。正式岗位必须由运营人员核对来源后发布。

后续已补充 PDF/DOCX 上传、原版文字编辑、原格式导出与三种站内模板，详见 [RESUME_FILES.md](RESUME_FILES.md)。AI 结构化简历解析/改写、真实导师排期/付款、资料商城仍未开放，界面不伪造成功结果。录音转写/Responses 报告沿用前一批独立 Worker 实现，仍需要 OpenAI Key、服务端配置与真实模型验收。

## 岗位目录迁移与运营权限

原有账号功能已经部署时，新增只需执行 `supabase/migrations/202610310003_public_catalog.sql`。它仅依赖最早的账号迁移，不要求先安装 AI 面试两份迁移。不要重跑已有账号迁移或清空用户数据。

新增：`job_catalog`、`site_managers`、个人记录的可空 `source_job_id`，以及按用户/岗位/类型去重的事务函数。公开角色只可读已发布岗位，草稿/下架记录不公开；运营用户可维护目录。普通用户不能插入运营角色，也不能修改发布数据。加入工作台默认状态是“未投递”，并不代表已经向招聘方投递。后续阶段已细化，见 [WORKSPACE_STAGES.md](WORKSPACE_STAGES.md)。

P0 后台已经升级为独立的 `admin_memberships` 三角色体系。既有 `site_managers` 行在新增迁移中保留为 editor，之后对旧表新增/删除行不再授予或撤销权限。不要继续使用旧版 SQL 配置权限。应执行 `202610310005_admin_workflow.sql`，然后由项目所有者安全初始化首个超级管理员；后续通过指定邮箱邀请和受控角色管理维护团队。具体目标邮箱、可点击配置地址与 SQL 见 [ADMIN_SETUP.md](ADMIN_SETUP.md)。

岗位保存为草稿后，依次提交审核、核验来源与投递方式、批准具体内容版本、发布。转正实习必须有 JD 中的留用原文。投递邮箱、标题要求、投递说明与完整 JD 绑定同一岗位，私有来源原件及审计不公开。正文修改需要重新审核；到期或下架不删除用户已保存的投递记录。超级管理员支持有明确核验说明的自审，适合个人运营，审核记录保留自审标记。

## 环境与部署

现有 Supabase URL、公开 key、服务端 key、APP_URL 沿用，无需新建账户或重新配置邮箱。首页、简历编辑和文字练习不需要 OpenAI Key。Vercel 继续使用 main；检查本次提交的部署是否 Ready，再刷新 `/`。

真实岗位发布需要执行目录和 P0 后台迁移，并按 ADMIN_SETUP.md 完成一次性初始化。未应用目录迁移时，主站和原有个人数据功能仍可用，岗位页面提供明确标注的样品预览；不会用静态样品冒充正式数据。
