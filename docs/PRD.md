# 上岸有期｜首版 MVP 产品需求文档（PRD） V1.3

**版本：** V1.3　**日期：** 2026-10-29　**状态：** 开发准备稿　**产品形态：** 响应式 Web（优先桌面端工作台、兼容移动端浏览）

## 0. 一页摘要

**产品愿景：** 从找实习／秋招岗位，到跟踪投递、打磨简历、准备面试，让求职信息与个人行动在同一个平台闭环。

**首版目标：** 做出可真实登录、可录入数据、可编辑保存的初始产品，而不是只看起来漂亮的静态网页。首版以「岗位聚合 + 横向表格求职工作台」为业务核心；面经、简历、AI 复盘和真人 Mock 保留可进入的基础界面或小规模试运营能力。

**产品原则：** ①品牌始终为「上岸有期」；②现代极简、年轻化，借鉴喜茶的留白与排版语言，但不复制品牌资产、不使用茶饮主题；③表格优先，允许用户自己编辑字段、状态、颜色、封面；④公共内容可信、来源可追溯；⑤私人数据默认私有；⑥首版控制复杂度。

**关键用户：** 大学生、应届毕业生、海外留学生；运营管理员；后续真人面试导师。

## 1. 范围和优先级

**本轮 Codex 的硬性交付边界：** 优先完成 M0 + M1 的岗位聚合、个人工作台、管理员后台；其余模块有真实入口、空状态和可扩展的数据模型，依资源决定是否追加简历基础功能。不要将支付、通话平台、未经许可的爬虫、扫描版 PDF OCR 作为首轮验收前置条件。

## 2. 用户角色与权限

| 角色 | 查看岗位/面经 | 保存个人投递 | 管理公共岗位/面经 | 管理导师/订单 |

## 4. 品牌与高保真 UI 规范

**品牌名不可改变：上岸有期。** 使用用户提供的 Logo 作为品牌参考，实际成品优先使用授权提供的透明底资源；不得自行把品牌改成茶饮、草本或其他名字。审美参考现代年轻品牌：黑白主基底、宽松留白、现代中文无衬线字体、少量富有辨识度的强调色；不要“中药馆绿金国潮”。

- 页面：桌面端最大内容宽度约 1440px；工作台允许全宽；移动端优先查看及简要编辑，不强求完整 Excel 密度。
- 组件：12px 左右中等圆角、轻边框、克制阴影；表头固定、行高 44–52px、支持横向滚动。
- 色彩：品牌色作为可配置 design token，而非写死在全部组件中；用户自选主题仅影响个人工作台，不影响公共品牌视觉。
- 导航：桌面侧边栏／顶部导航；移动端精简顶部导航和底部快捷入口。
- 必须有：加载骨架、空状态、错误态、保存成功提示、删除二次确认、搜索零结果提示、移动端布局。
- 无障碍：键盘可访问、状态不只靠颜色表达、对比度合适、图标有语义。

## 5. 核心功能需求

### 5.1 岗位聚合（JOB）

**JOB-01 [P0] 分类：** 日常实习、转正实习、秋招、春招；支持届别、城市、行业、公司、岗位关键词筛选。默认按核验/发布时间排序，明确区分两者。

**JOB-01A [P0] 转正实习的严格定义与标注（V1.4 新增）：**「转正实习」表示招聘方在可核验的 JD 或官方招聘信息中明确写有「有留用可能」「有留用机会」「表现优秀可考虑留用」「考核通过有机会转正」等条件性表述；**仅表示存在留用可能，不承诺转正，不得展示为「保转正」或「保证留用」**。如果来源没有明确写出留用/转正机会，则不因岗位名称含“暑期实习”、实习时长较长或 AI 猜测而归入此类，应归为「日常实习」或交由人工复核。

**JOB-01B [P0] 前台展示：** 在转正实习岗位详情的 JD 同一内容区显示「**留用情况：有留用可能（以招聘方实际考核及安排为准）**」，并展示支持该判断的原文片段及来源链接（若可获取）；不得把条件性机会呈现为明确承诺。列表标签保持简短的「转正实习」，必要时用提示说明含义。

**JOB-01C [P0] 后台字段与审核：** `job_type` 允许 `daily_internship`、`conversion_internship`、`autumn_recruitment`、`spring_recruitment`；增设 `retention_opportunity`（`possible`/`unspecified`）、`retention_evidence_text`、`retention_evidence_url`。AI 只给建议分类与证据，不能自行构造原文；管理员确认后才能发布。已有转正实习岗位需按来源重新核验，不符合条件则调整分类。

**JOB-01D [P0] 验收：** 有明确「表现优秀有留用机会」的 JD 可归入转正实习，详情显示条件性提示；未提及留用的 JD 不自动归类；明确写「不提供转正」不得归类；所有筛选、搜索、导入、编辑和发布使用同一定义。

**JOB-02 [P0] 岗位卡片：** 公司、岗位名称、城市、类型、毕业届别（如适用）、最近核验日期、招聘状态、投递来源。允许收藏与加入工作台。

**JOB-03 [P0] 岗位详情：** 结构化 JD、任职要求、投递方式、原始来源链接、发布时间及核验时间；明确站外跳转，不能把“点击投递”当作已成功投递。

**JOB-04 [P0] 状态：** 草稿/待审核/已发布/已过期/已下架；过期内容不默认参与正常搜索，可提供历史标识。

**JOB-05 [P1] 关联：** 对应公司面经、岗位准备资料、加入用户工作台的入口。

### 5.2 横向 Excel 风格求职工作台（WS）

**WS-01 [P0] 默认布局：** 桌面端横向整页表格，冻结「公司/岗位」列、表头固定，其他列横向滚动；提供行 hover、键盘焦点、紧凑/舒适密度切换（密度可 P1）。

**WS-02 [P0] 行字段：** 公司、岗位、招聘类型、城市、当前状态、投递日期、下一步日期、投递链接、备注、关联简历版本（可先占位）、面试复盘入口（可先占位）。

**WS-03 [P0] 编辑：** 行内单元格点击即编辑；日期选择器；可新增/复制/删除行；未保存修改提供自动保存/保存提示；验证日期和链接格式。

**WS-04 [P0] 状态：** 默认「想投递、已投递、笔试/测评、一面、二面、HR 面、Offer、已拒绝、暂停」；支持用户添加/重命名/调整顺序/修改颜色；状态变更只作用于本人记录。

**WS-05 [P0] 个人化：** 用户自定义状态颜色、工作台主题与封面（优先内置图片/纯色；自上传图片 P1）、头像、表格名称。

**WS-06 [P1] 列定制：** 显示/隐藏/排序列；新增文本、日期、数字、选择、复选框和链接类型的自定义字段。

**WS-07 [P1] 数据流：** 从站内岗位一键创建用户记录并避免重复；站外岗位手动添加；CSV 导入/导出（Excel xlsx 可 P2）。

**WS-08 [P2] 辅助视图：** 同一数据源的看板拖拽与日历视图，不另建一套独立数据。

**WS-09 [P0] 数据隔离：** 本人读写自己的所有投递，其他用户不能通过 API 读取或修改。

### 5.3 面经中心与动态发现（INT）

**INT-01 [P0]** 面经按公司、岗位、轮次、内容类型分类；每条明确标注原创／授权转载／外部线索。

**INT-02 [P0]** 外部线索卡片展示标题、来源平台、合法链接、发现日期以及允许展示的元信息；不默认复制全文或售卖第三方帖子。

**INT-03 [P1]** 运营后台支持链接提交、去重、审核、失效标记、版权/授权记录。

**INT-04 [P2]** 授权数据源连接器、定时更新与订阅提醒；小红书、牛客等平台是否有合法可用接口须单独确认，不能承诺全网实时覆盖或绕过访问控制。

**INT-05 [P2]** 面经商城仅销售平台原创或取得商业使用授权的资料，附购买权限、退款、版权说明等完整交易流程。

### 5.4 智能简历（RES）

**RES-01 [P1]** 仅接收 `.docx` 和包含可提取文字的 `.pdf`；拒绝扫描 PDF 与图片 OCR，提供清楚的失败提示。

**RES-02 [P1]** 识别教育、实习、项目、技能等块；用户必须可校正解析结果，保留原始文字与格式信息。

**RES-03 [P1]** 左侧块编辑、右侧 A4 预览；支持内容增删、排序、另存岗位版本和导出 PDF。

**RES-04 [P2]** 上传模板的版式尽量保留，但不承诺任意 Word/PDF 100% 原样编辑；复杂 PDF 需重建并提示偏差。

**RES-05 [P2]** AI 优化建议必须以用户已有经历为依据，不编造学校、任职、指标或证书；用户确认后再替换。

### 5.5 AI 面试复盘（REV）

**REV-01 [P1]** 绑定岗位、面试轮次、日期；用户可手动输入面试问题、实际回答、备注，形成可编辑复盘。

**REV-02 [P1]** 后端调用 OpenAI API 生成：问题整理、回答优缺点、可执行改进建议、下次准备清单；显示 AI 辅助标识，允许用户纠正。

**REV-03 [P2]** 支持上传经合法录制及上传授权的音频并转写；允许人工校对、手动修正发言人、删除录音；在录音授权不明确时引导文字录入。

**REV-04 [P2]** 原始音频、文字稿、分析结果分别管理存储与删除；请求需要配额、超时、成本限制和重试机制。

### 5.6 真人 Mock（MOCK）

**MOCK-01 [P1]** 展示经过审核的导师资料（资历核验标识、擅长岗位、语言、服务时长），支持提交预约意向；M1 可由运营人工确认。

**MOCK-02 [P2]** 空闲日历、预约冲突、支付/退款、视频会议链接、导师反馈表、售后评价、投诉与仲裁流程。

**MOCK-03 [P0]** 简历与用户真实面试记录不默认分享给导师；每次分享单独授权。

### 5.7 运营后台（ADM）

**ADM-01 [P0]** 管理员登录与角色校验；岗位新增、编辑、草稿、待审核、发布、下架、失效。

**ADM-02 [P0]** 粘贴原始 JD，生成可编辑结构化字段；可先使用规则提取与人工修正，AI 解析接入不应阻止基础发布。

**ADM-03 [P0]** 保存来源 URL、来源类型、核验人、核验时间、审核意见；同公司+相似岗位+投递链接做重复预警。

**ADM-04 [P1]** 面经文章、外链、授权状态管理；可审核投诉及链接失效反馈。

**ADM-05 [P0]** 关键发布、下架、权限变更写入审计日志；不允许前端直接绕过后端权限修改公开数据。

## 6. 关键用户旅程与页面交互

**旅程 A｜找岗位：** 首页 → 选择「秋招」 → 筛选城市/行业/届别 → 查看 JD 和来源 → 跳转官方投递 → 用户主动确认已投递 → 记录进入自己的工作台。

**旅程 B｜管理投递：** 登录 → 横向表格 → 「+ 新增一行」 → 填公司/岗位/日期 → 下拉修改状态及状态颜色 → 添加备注 → 自动保存 → 重新登录后仍保持。

**旅程 C｜准备面试（后续）：** 从某条投递记录 → 查看相关面经 → 打开绑定简历版本 → 创建 AI 复盘 → 需要额外训练时预约真人 Mock。

**旅程 D｜运营发布：** 管理员 → 粘贴 JD → 自动/规则提取 → 手动校正 → 来源核验 → 审核发布 → 前台可搜索 → 定期检查过期。

## 8. 非功能要求与安全

- 搜索和列表应分页；关键交互有加载及失败状态；普通网络条件下优先保证首屏可用。
- 服务端保护 OpenAI 和数据库管理员密钥；导入文本和上传文件做格式、体积与恶意内容检查。
- 对外部 URL 做安全校验，防止脚本注入及不安全跳转；用户输入展示时转义。
- 图片、简历、面试录音分私有存储桶及带时效的授权读取链接；允许删除和导出个人数据。
- 首版不承诺任何岗位真实开放、录取结果、AI 评分客观性或第三方平台实时抓取完整率。
- 正式对公众开放招聘服务、收费服务、录音处理和第三方内容使用前进行适用法规、平台条款、版权、隐私、支付与退款机制核查。

## 9. 首版验收标准（Definition of Done）

| ID | 验收场景 | 通过条件 |

| AC-01 | 游客看岗位 | 能按四类招聘类型及关键词过滤，查看详情及真实来源字段 |

## 12. 需求增补（V1.1）：智能搜索与岗位投递信息一体化

### SEARCH-01 [P0] 全站模糊搜索
- 一个搜索框可检索公司、岗位、面经、招聘批次等已收录内容，并按内容类型分组呈现。
- 支持企业名称、简称、英文名、常见别名联想，例如“中金”联想“中金公司/CICC”；但不误把其他名称含“中金”的公司自动合并。
- 支持岗位简称、同义词和常见写法映射，例如“财务”扩展到“财务BP”“财务分析”“账务”等有明确相关性的类别；优先返回直接匹配的结果，其次相关联想结果。
- 搜索联想与结果只引用已入库且符合公开权限的记录，不捏造岗位；提供分类、关键词高亮和无结果状态。

### SEARCH-02 [P0] 精准搜索
- 搜索框旁提供“模糊搜索／精准搜索”切换，默认模糊搜索；用户可随时切换并保留关键词。
- 精准搜索不扩展同义词及其他公司别名，基于明确的公司、岗位或字段匹配规则；结果仍可按岗位/面经/招聘批次筛选。
- 企业别名表与岗位同义词表由后台维护、可纠错，支持人工排除歧义。

### JOB-05 [P0] 投递邮箱与岗位详情一体化
- 投递邮箱、投递链接、投递方式及邮件主题要求，属于该岗位自身的 `application` 信息，**不可拆成单独的邮箱栏目、独立招聘卡片或独立岗位条目**。
- 岗位卡片可在内容底部显示“投递方式：邮箱/官网/其他”，不必强制把完整邮箱放入列表；进入岗位详情后，在 JD 正文及岗位要求同一个详情内容区域展示完整投递信息。
- 邮件投递展示邮箱地址及“复制邮箱”“发送邮件”按钮（mailto）；如有邮件主题格式则一同展示与复制。官网投递展示原始链接及来源提示。
- 一个岗位允许邮箱和官网同时存在，允许多个邮箱（注明主投递邮箱或不同部门用途）；禁止以邮箱作为去重主键。
- 后台新增/编辑 JD 时，邮箱和投递方式与岗位正文同一个编辑表单填写、审核、更新；来源待核验时显示提示，不能凭 AI 臆造邮箱。
- 验收：用户从岗位列表进入详情，不需跳转另一个“邮箱页面”就能看到并复制对应岗位的投递邮箱；复制只含该岗位已核验邮箱。

### 建议数据字段
- `companies`: `canonical_name`, `aliases[]`（或独立 `company_aliases` 表）。
- `job_synonyms`: `canonical_term`, `alias_term`, `category`, `status`。
- `jobs`: `application_method`, `application_url`, `application_subject`, `application_instructions`, `source_verified_at`。
- `job_application_contacts`: `job_id`, `email`, `label`, `is_primary`, `verified_at`（用于一个岗位对应多个邮箱）。


## 13. 需求增补 V1.3｜微信扫码登录、品牌 Logo 与个人数据持久化

### AUTH-01 [P0] 微信扫码登录
- PC 网页提供“微信扫码登录”主入口，真实二维码由微信开放平台授权流程生成；不得生成静态或伪造的登录二维码。
- 接入条件：申请并获批适用的微信开放平台网站应用，取得 AppID/AppSecret，设置授权回调域名与生产 HTTPS 域名。未就绪时展示明确的“尚未配置”状态，原型仅展示扫码流程示意。
- 服务端发起 OAuth 授权请求、校验 state、处理回调并建立自身会话。凭证仅保存服务端，防 CSRF、重放和会话固定；禁止以用户昵称作为唯一账号标识。
- 微信账号关联到内部唯一 user_id。合理使用返回的身份标识；涉及同一微信生态不同应用的账号互通时按官方规则设计 unionid/openid 映射，不假定总有 unionid。
- 需要有审核未完成时的开发备用登录方式（仅测试环境），不能把模拟认证暴露给线上用户。

### AUTH-02 [P0] 首次登录、资料与个人工作空间
- 首登建档：昵称、头像（可选）、学校、专业、毕业届别、求职偏好（均可跳过非必要项），并创建个人工作台默认状态与设置。
- 所有 application_records、workspace_preferences、resume_versions、interview_reviews、收藏、Mock 订单等归属内部 user_id。
- 登录后跨设备读取自己的记录；支持安全退出、登录过期提示、修改个人资料、删除账号与数据导出申请。
- 用户上传的头像与工作台封面支持替换、删除，文件私有或按可见范围管理，校验类型/大小并剥离敏感元信息。
- 首版工作台可设置单独的个性化主题、封面与状态颜色，公共站点品牌视觉保持统一。

### BRAND-01 [P0] 左上角使用官方 Logo
- 用户提供的“上岸有期”Logo 是正式品牌资产；所有桌面顶栏、移动端顶栏、登录页、工作台、运营后台均引用同一资源。
- 不得使用临时的“期”字方块替代，不得使用其他品牌名或无关茶饮/草本图案；导航栏使用适配尺寸，保持比例不裁切文字。
- 原始图为方形且有白色背景，初版可以先在独立白色 Logo 容器中使用；后续设计透明横版资产，但不能在未经确认时修改官方标志。

### SEARCH-03 [P0] 智能搜索统一入口
- 在首页/岗位列表提供一个统一查询框和“模糊/精准”切换。模糊模式支持公司简称、常用英文名和岗位同义词，例如“中金”→“中金公司/CICC”，“财务”→“财务BP、财务分析、账务”等（仅返回实际存在的内容）。
- 搜索结果分类展示公司、岗位、面经、招聘批次；公司名称映射须人工维护与纠错。精准模式仅按明确规则匹配，不扩展语义同义词。
- 结果提供信息来源与状态，不能捏造实时空缺、招聘时间或面经文章。

### JOB-06 [P0] 投递邮箱属于岗位内容
- 投递邮箱、邮件标题要求、官网投递链接与注意事项在同一岗位详情版块内展示，并在后台同一 JD 表单录入、审核。
- 邮箱不得拆成独立栏目、独立页面或单独的一条招聘记录。支持复制邮箱、邮件按钮，支持一岗多邮箱与多投递方式。
