# 简历文件上传、原版编辑与模板

原来的编辑器只提供固定 A4 分块排版，没有文件上传，也不能保留用户已有模板。本次保留原编辑器和全部旧记录，增加原文件编辑模式，以及三个可选择的站内模板。入口仍为「我的求职 → 我的简历」`/resume`，所有编辑页继续显示全站导航。

## 两种编辑方式

| 方式           | 编辑与导出行为                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 上传 DOCX      | 提取正文、页眉、页脚，按完整段落和表格行检索；编辑文字及选定的段落/文字格式，保留其余样式、表格、图片与页面设置。导出仍为 DOCX。            |
| 上传文字型 PDF | PDFium 在原页面替换可识别的文字对象，保留原位置、字号、颜色及未修改元素；导出仍为可选择文字的 PDF，不用截图重建。修改文字使用兼容中文字体。 |
| 新建站内模板   | 经典单栏、紧凑履历、侧栏信息三种版式，可切换、分块编辑、预览、云端保存；导出真正的 DOCX 或浏览器打印 PDF。                                  |

上传不会自动转换成站内默认模板。「下载原件」始终返回上传时的原始字节；「导出 Word / PDF」应用当前文字修改。需要改用站内版式时，点击「另建模板副本」，再校对和整理导入文字，原版记录继续保留。「另存新版本」也创建独立记录和私有原件，不覆盖其他版本。

修改内容与模板选择保存到原有 `workspace_entries`，继续绑定既有内部 `user_id`。原文件不可变，修改以文字片段键值保存；重新打开时从原件应用修改。版本更新使用 `expectedUpdatedAt`，冲突返回 409，避免覆盖另一设备已保存的内容。未保存稿仍按用户和标签页隔离暂存。

## Word 排版与完整上下文

1. 搜索标题前几个字，例如「项目经历」，会显示完整段落及冒号后的所有文字片段。关键词跨越多个粗体/普通文字片段仍可命中；表格中的标题命中时，也显示同一行其他单元格。支持搜索修改后的文字，并保留按原文找到该段的能力。
2. 展开「段落排版」调整对齐、左右缩进、段前段后间距和行距。「段落左移 / 右移 1 mm」同时移动两侧边界，保留段落宽度，所以右对齐的日期也会移动。
3. 对使用原生右对齐制表位排在行末的日期，可用「日期左移 / 右移 1 mm」或直接填写末尾制表位。该操作改动原生 Word 制表位，保留左侧公司/学校文字的位置；继承自段落样式的旧制表位会在本段清除，保证导出后的移动也生效。该入口在识别到右制表位时显示；普通独立日期或表格里的日期段落可用段落微调。普通制表符需先在 Word 设置右制表位，浮动文本框不提供拖拽重排。
4. 每个文字片段可调整字号和上下位置，正数上移、负数下移。控制值写入原生 Word `w:sz` / `w:position`，不只改变网页 CSS。
5. 停止输入约 400ms 后自动预览，也可点「更新预览」。预览显示排版中、更新成功或失败信息；新排版准备完毕再替换上一张成功结果，连续输入只提交最新结果。预览更新不等于云端保存，仍需点「保存原版修改」。

旧版 Word 预览参数 `inExperimentalMode` 实际未被库识别，制表位曾按普通空白显示；现使用受支持的 `experimental` 选项，并在原尺寸完成制表位计算后缩放预览。预览和导出使用同一份原件及修改数据，失败不会清空原件。新增格式字段沿用 v1 元数据结构与原文字键，旧记录不需要迁移或重传；没有新增环境变量、SQL 或外部转换服务。

## 支持范围

- 单个文件最多 3 MiB，每用户每小时最多 20 次上传，最多保留 60 份原版文件记录；另存原版也占记录额度。编辑信息最多 300 个片段、合计 20,000 字符 JSON。
- 支持 `.docx` 和 `.pdf`；旧版二进制 `.doc` 需要先在 Word/WPS 中另存为 DOCX。宏及嵌入程序不受支持。
- DOCX 提供原文字片段编辑与基本排版微调，支持对齐、缩进、间距、行距、日期制表位、字号和上下位置，仍不是完整 Word 处理器。更改任意长度的文字或行距后，分页可能变化；超链接地址、域代码等不会因改显示文字而自动更新。浏览器字体和分页可能与 Word/WPS 不同，浮动文本框、复杂形状等仍需原应用调整。需要 PDF 成品时可在 Word/WPS 中将编辑后的 DOCX 导出为 PDF。
- PDF 最多 20 页、1,500 个可编辑文字片段。仅编辑页面顶层文字对象；扫描件和嵌套表单中的文字不做 OCR 或强制转换。签名或带修改限制的文件只读。PDF 不自动扩行，旋转/倾斜文字、超出页面及字体不支持的字符会明确报错，不静默丢字。修改处的字体字形、粗细可能与原字体不同；其余对象保持原版。若需要改大段内容和布局，优先使用 DOCX。
- 没有新增 AI 调用、OpenAI Key 或付费文档转换服务，也不把简历发送给外部解析网站。此功能不依赖尚未开放的 AI 简历改写。

## API 与私有存储

| API                               | 用途                                                       |
| --------------------------------- | ---------------------------------------------------------- |
| `GET /api/resumes`                | 原有版本列表或指定版本；区分站内模板和原版文件。           |
| `POST /api/resumes/upload?name=…` | 已登录同源二进制上传，流式限制大小、验证格式及额度。       |
| `GET /api/resumes/[id]/file`      | 验证本人记录后代理下载原件，校验长度及 SHA-256；禁止缓存。 |
| `POST /api/resumes/[id]/file`     | 验证所有权后把当前文字修改应用到 DOCX，并下载。            |
| `PUT /api/resumes/[id]/original`  | 保存标题和修改，保留原件；校验并发版本。                   |
| `POST /api/resumes/[id]/original` | 用当前修改另存独立原版记录。                               |
| `DELETE /api/entries`             | 删除当前版本及对应原件，其他版本保留。                     |

PDF 通过本站静态 WASM Worker 在浏览器处理，中文字体经 HarfBuzz 按需子集化后嵌入，避免每份 PDF 附带完整字体。所用 PDFium、HarfBuzz、Noto 字体的许可随资源保存在 `public/vendor/resume` 与 `public/fonts/resume`。

原件存入 Supabase **私有**桶 `resume-originals`，路径仅由服务端的 `user_id`、数据库生成的记录 ID 和受限类型生成。浏览器不得提交存储路径、所有者或服务端密钥。下载先以用户会话查询拥有该记录，再以服务端凭证读取文件；不发放公开 URL。元数据继续受原 PostgreSQL RLS 保护，匿名或其他用户无法读取、改写或导出。

首次上传会使用已有服务端配置创建私有桶，不需要新增环境变量。可在部署迁移时执行 [202610310004_resume_originals.sql](../supabase/migrations/202610310004_resume_originals.sql)，显式创建桶并增加限制性策略，防止未来其他宽泛 Storage 策略意外开放该桶。该迁移不修改用户资料、内部 ID 或旧简历记录。

单份删除先删除原件再删除记录，Storage 失败时保留记录并返回可重试错误。清空个人数据、注销账号会清理本人目录。上传预留元数据并在上传后重新检查，失败时补偿清理，以处理与数据删除的竞争。数据库和 Storage 不属于同一事务；持续基础设施故障下可能需要运营核对孤立私有文件，本版本没有新增常驻的简历文件清理 Worker。

## 验证方法

在本机测试库启动应用后运行：

```bash
npm run test:resume-files
npm run test:resume-layout
npx playwright test tests/resume-files.e2e.ts
```

测试使用自建的合成 DOCX/PDF，真实 Auth、PostgreSQL 和私有 Storage，不接触生产简历。文件专项测试以本地真实 Auth 的一次性验证链接建立会话；原邮箱 OTP 测试仍独立验证收发邮件。测试目标包括：

1. 上传两种格式，下载原件与上传字节完全一致，刷新及另一会话读回同一记录。
2. A/B/匿名隔离、同源校验、无效格式、文件大小限制及旧版本冲突。
3. DOCX 修改后可读回新文字，其余 19 个文档部分逐字节一致，包含样式、图片、页眉页脚；原件不变。
4. PDF 新文字仍可选中、旧文字确实移除，未改的第二页及第一页非修改区域像素不变；连续删除与修改多个片段不会错位。
5. 两种原版的真实网页上传、编辑、导出、保存和刷新；明确转换模板副本，原版本继续保留。
6. 单份删除、清空个人数据及账号注销清理本人原件，同时保留另一个用户数据；手机不横向溢出且保留四项导航。
7. Word 标题/冒号/正文拆为多个运行片段及表格行时仍能检索完整上下文；日期微调、字号和上下位置可保存、刷新及原格式导出。浏览器测量日期和公司坐标，确认只移日期；另测右对齐的独立日期段落。

最终运行结果记录在 [TESTING.md](TESTING.md)。生产环境的部署状态与托管 Storage 访问仍需独立验收，本地结果不代表线上已更新。
