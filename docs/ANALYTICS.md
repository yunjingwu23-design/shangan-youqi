# 数据分析中心与管理员审计

首版使用站内第一方采集与 Supabase 聚合，不依赖第三方分析 SDK、广告标识或额外服务凭证。`/admin/analytics` 是正式分析入口，旧 `/admin/data` 复用同一仪表盘。授权范围沿用启用的 super_admin、editor、reviewer；普通用户及停用管理员无法通过页面、API 或直接 RPC 读取统计。没有虚构流量或历史数据回填。

## 数据库升级与发布顺序

已安装后台的项目依次应用：

1. `supabase/migrations/202611010001_admin_otp_without_time_limit.sql`：取消团队管理的额外 15 分钟 OTP 时间窗。保留有效邮箱会话、当前启用角色、限流、邀请有效期及最后一位超级管理员保护。
2. `supabase/migrations/202611010002_site_analytics.sql`：私有事件存储、聚合 RPC、保留期清理和按会话去重的管理员登录审计。

CLI 管理的项目按原迁移账本部署；SQL Editor 管理的已有项目由项目所有者以 postgres 身份执行这两份文件的全部 SQL，不重跑历史迁移、不重新初始化管理员、不 reset 数据。新增分析迁移可重复执行，保留采集起始时间与已有事件。`supabase/install-admin.sql` 已包含两个更新；合并入口适用于首次安装或依赖修复，重复执行不会恢复 15 分钟限制，也不会清空分析记录。

先升级目标数据库，再部署应用代码；部署成功后用真实授权管理员验收页面、API、日志及至少一次同意采集后的访问。当前本机测试结果不能代表托管数据库已升级或公网部署成功。现有 `NEXT_PUBLIC_SUPABASE_URL`、公开 key、`SUPABASE_SERVICE_ROLE_KEY`、`AUTH_RATE_LIMIT_SECRET` 和 `APP_URL` 保持成套使用，**没有新增依赖或密钥**。HMAC 复用限流密钥但使用独立命名空间；轮换该密钥会使原统计 Cookie 失效并改变去重口径。

## 指标口径

日期使用 Asia/Shanghai（北京时间）的自然日，开始和结束日期都包含当天；自定义范围只接受最近 90 天，最多 90 天。支持今天、昨天、近 7 天、近 30 天。访问趋势补齐无事件日期的真实零值，统计加载失败显示错误而非假零。

| 指标              | 计算方法与限制                                                                                                                                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PV                | 已同意采集且服务端接受的 page_view 次数。SPA 路径和岗位分类切换算页面浏览，普通查询参数不拆成页面。事件 UUID 重复提交不重复计数。管理页与 API 不采集 PV。                    |
| UV                | 期间第一方随机浏览器标识的去重数，不是每日 UV 相加。跨设备、清除 Cookie、统计标识过期会被视为新访客，不做设备指纹。                                                          |
| 注册用户数        | 日期范围内创建且当前仍存在的 app_users 账号数量，包括已建档、尚待邮箱验证的账号，不代表通过身份核验的人数；注销的账号不再参与查询。来自账号表时间聚合，不依赖流量同意。      |
| 活跃用户数        | 期间存在已采集事件的去重登录账号散列标识。匿名访客不计入活跃账号。                                                                                                           |
| 来源              | 页面浏览的来源类别：直接、站内、百度、Google、Bing、微信、社交及其他外部；只保存类别，不保存原始来源 URL、来源查询参数或未知站点主机名。不是会话级获客归因。                 |
| 分类浏览与点击    | 分类列表浏览及已发布岗位详情浏览归入四类；分类入口点击和岗位卡片点击单独记录，表中提供详情浏览数。未核验的交互样品不计入真实岗位排行。                                       |
| 收藏 / 加入工作台 | 服务端真实保存成功且首次创建时计一次；重复点击已有记录不重复计数。删除后重新保存会形成新事件。                                                                               |
| 投递链接点击      | 招聘方投递链接的点击意向，不等于成功投递；也不把加入工作台视为已投递。本系统没有招聘方的成功回执。                                                                           |
| 公司 / 岗位排行   | 通过真实岗位 ID 关联目录，展示详情浏览、岗位点击、投递链接点击和保存事件。名称采用当前目录名称；删除岗位后相应排行不再关联，期间总事件数仍保留。                             |
| 热门搜索          | 仅发送 `lib/analytics/model.ts` 中明确列出的公开岗位、公司及城市词；任意原始搜索、个人记录标题、邮箱或长文本不发送。少于三位去重访客的词不进入排行。后续可审阅扩展公开词表。 |
| 简历编辑器        | 页面访问、成功保存和原文件上传的次数。不会采集标题、文件名、正文、编辑内容或原件。                                                                                           |
| AI 面试复盘       | 页面访问、创建录音记录及成功提交报告生成请求的次数。创建不等于上传完成，请求不等于报告生成完成；不记录录音、逐字稿或报告。功能开关关闭时展示关闭状态和实际已采集值。         |
| 真人 Mock         | 页面访问和已保存意向次数。导师预约、支付和真实服务尚未开放，不展示伪造预约或完成数。                                                                                         |

除注册数据及权限审计外，使用和流量统计仅覆盖同意采集且未被浏览器阻止的访问，不能代表全站完整流量。浏览器请求属于尽力采集，断网、插件、机器人 UA 过滤及未同意采集都会造成缺口。

## 采集与隐私边界

访客通过页尾“统计偏好”选择允许或拒绝，拒绝不影响原有功能。第一方统计 Cookie 为 HttpOnly、SameSite=Lax，正式 HTTPS 使用 Secure，有效期 90 天；随机值带服务器 HMAC 签名，不接受伪造标识。数据库只存不可读的访客 / 账号 HMAC，不存原始 IP、Cookie、邮箱、姓名、完整 URL、查询参数、设备指纹或任意自由格式 metadata。DNT=1、GPC=1、已识别自动流量及预取请求不写入事件。

`POST /api/analytics/events` 同源校验、2 KiB 请求体上限、严格字段与事件白名单、每访客每分钟 300 次及每 IP 桶每分钟 1000 次的原子数据库限流。IP 仅用于现有限流器中的 HMAC，不进入分析事件。客户端不能伪造收藏、简历保存、AI 请求或 Mock 意向等服务端业务事件；已发布岗位元数据由服务端查表，客户端不能提交公司或岗位正文。

所有事件保存在不暴露给 PostgREST 的 `private.site_events`，启用 RLS 且不给 anon/authenticated 表权限。写入、清理和擦除函数只授予 service_role。`admin_site_analytics(date,date)` 在数据库内重新检查当前启用的管理员角色，只返回聚合，不返回访客 / 用户散列或原始事件。服务端同时调用 getUser 验证会话。

撤回同意会删除当前浏览器标识对应的事件并停止后续采集；本站的删除个人数据和注销账号会擦除该账号散列对应事件。私人简历、录音、复盘、Mock 回答及其他敏感个人内容均不进入埋点。公开隐私说明为 `/privacy`，运营方可结合实际主体、服务地域及现有对外联系渠道维护完整隐私政策。

## 保留期与维护

事件查询仅覆盖最近 90 天，写入时每日首次采集自动清理超期事件。为在无流量期间也及时清理，应在可信服务器 / Supabase 项目调度系统每天调用：

```sql
select public.cleanup_site_analytics();
```

或使用既有服务端配置运行 `npm run analytics:cleanup`。该命令只输出删除条数，不能在浏览器暴露管理 key。当前代码没有代替运营方创建生产定时任务。不要把本机 `.env.local` 或开发凭证用于正式项目。

## 审计追溯

沿用 `admin_audit_logs` 与 `job_reviews`，JD 新建、修改、提交审核、批准、驳回、发布、下架及权限操作仍与业务事务同时写入，包含实际账号、角色、岗位 ID、版本、状态前后值及说明。浏览器无法改写或删除日志。

新增 `admin_login`：邮箱登录后、或真实 Auth 会话首次进入后台时记录一次，以 Auth 的 session_id 去重，刷新页面不重复计数。普通用户不产生管理员登录日志。安全审计独立于流量同意，系统权限与登录日志继续只向超级管理员开放；其他角色仅查看其已有权限范围内的岗位日志。仪表盘仅展示操作数量并链接原日志页面。

npm start

npm run typecheck

测试只允许本机数据库，创建一次性账号、真实岗位和事件，结束后清理自己的夹具。覆盖去重、期间 UV、北京时间边界、公开搜索词阈值、真实保存、撤回删除、保留期、页面/API/RPC/表权限、15 分钟前 OTP 会话及实际审计账号。浏览器会实际选择同意、浏览岗位、收藏、加入工作台、点击投递链接并检查统计页面，截图为合成测试数据。
