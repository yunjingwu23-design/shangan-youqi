# 首版 P0：运营后台与岗位审核发布

## 开发顺序

首版 P0 同步包含现有邮箱登录/内部 user_id、公开岗位广场与运营后台。已有私人工作台、原版简历、四模块导航及录音复盘内测需求继续保留。本次先交付真实的「管理员登录 → 手工导入 JD → 保存草稿 → 提交审核 → 审核通过 → 发布 → 前台读取」闭环，再开发 AI 字段提取、Excel/CSV 批量导入及其他内容运营。未完成能力明确标注，不自动编造或公开发布。

## 数据库结构

继续复用 `app_users`、`profiles` 和 `job_catalog`，不重建内部 ID，不删除现有岗位或用户记录。

| 表                  | 主要内容与访问范围                                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `admin_memberships` | 内部 user_id、super_admin/editor/reviewer、启用状态、授权人员和时间。本人可读自己的角色，超级管理员管理团队。          |
| `admin_invitations` | 绑定邮箱与角色的一次性邀请、令牌哈希、48 小时有效期、创建人和领取信息。只有超级管理员创建/撤销。                       |
| `job_catalog`       | 一条岗位及其分类、职责、要求、投递邮箱、投递链接、邮件标题和投递说明、截止时间、公开状态。前台只读未过期的已发布岗位。 |
| `job_admin_meta`    | 岗位版本、内容修订号、创建/修改人员、提交/审核人员与时间、获批修订号、当前来源快照。仅管理员读取。                     |
| `job_sources`       | 每次保存的原始 JD/校订文本、来源地址、来源发布时间、原文件关联、操作人。来源快照只追加。                               |
| `jd_import_files`   | 私有原件的文件名、格式、大小、SHA-256、原始提取文字、上传人、关联岗位。原件保存在私有 Storage，不发放公开链接。        |
| `job_reviews`       | 提交、批准、驳回、发布、下架、过期的版本与理由、审核人员和时间。只追加。                                               |
| `admin_audit_logs`  | 岗位与权限操作、实际操作人、角色、目标、版本、状态前后与说明。只追加，普通用户不可读。                                 |

`site_managers` 的已有授权迁为 editor，旧标记不再作为提权入口。已有已发布岗位保留，以迁移快照记录历史来源；新编辑必须重新走审核。业务写入使用已认证用户的受控数据库 RPC，在同一事务内检查权限、版本、状态并追加审计。撤销浏览器直接更新岗位/角色/日志表的权限。

状态：草稿 → 待审核 → 已批准 → 已发布；驳回返回修改，下架和到期从公开列表移除。已发布岗位编辑前先开始修订并撤回公开，重新审核后发布。批准绑定具体内容修订号，不能审核后替换正文再发布。

## 角色权限矩阵

| 能力                             | 普通用户 | editor         | reviewer                   | super_admin                      |
| -------------------------------- | -------- | -------------- | -------------------------- | -------------------------------- |
| 浏览公开岗位                     | 是       | 是             | 是                         | 是                               |
| 进入后台/读运营岗位与来源        | 否       | 是             | 是                         | 是                               |
| 录入/导入 JD、保存草稿、提交审核 | 否       | 本人岗位       | 否                         | 全部                             |
| 批准/驳回                        | 否       | 否             | 是，不能审核本人创建的岗位 | 是；本人岗位必须明确记录自审说明 |
| 发布已批准版本、下架、过期处理   | 否       | 否             | 是                         | 是                               |
| 邀请、调整或停用管理员           | 否       | 否             | 否                         | 是，要求近期邮箱验证             |
| 查阅操作日志                     | 否       | 仅岗位相关记录 | 仅岗位相关记录             | 全部                             |

首个超级管理员只通过可信服务端或 Supabase 项目所有者的初始化函数建立，要求已有且已验证的 Auth 邮箱，只能首次初始化。不能通过普通注册、客户端 user_metadata 或公开 API 自动成为管理员。邀请领取必须是目标邮箱的真实登录会话，校验有效期、单次使用及邀请人仍有超级管理员权限。保留至少一个启用的超级管理员，账号注销前也检查。

## 页面清单

后台独立使用官方 Logo 和四个管理分区，普通前台导航不出现后台入口。所有具体编辑、来源、审核页面保留后台导航。

| 地址                                  | 内容                                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------------------- |
| `/admin`                              | 真实运营概览、待审/草稿/公开/过期统计、常用操作。                                     |
| `/admin/jobs`                         | 横向 JD 管理表格、关键词/状态/类型筛选和分页。                                        |
| `/admin/jobs/new`、`/admin/jobs/[id]` | 同一编辑组件：粘贴原文、TXT/DOCX/文字型 PDF、人工填写字段、重复提示、保存及状态操作。 |
| `/admin/review`                       | 待审核工作台，打开完整 JD、原件与来源，记录审批理由后操作。                           |
| `/admin/system`                       | 管理员账号列表、邀请创建与撤销、角色变更和停用。                                      |
| `/admin/accept`                       | 指定邮箱登录后领取单次邀请，不接受客户端指定角色。                                    |
| `/admin/logs`                         | 权限及岗位操作日志。                                                                  |
| `/admin/data`、`/admin/services`      | 保留数据中心和服务运营分区，未实现服务标明状态。                                      |

## 导入与审核规则

P0 支持粘贴、UTF-8 TXT、DOCX 和文字型 PDF，单文件 3 MiB，原件私有保存。文件转成原文，人工填写/校订结构化字段，不把文本提取伪装成 AI。扫描 PDF 明确提示不支持 OCR。来源地址、原文、投递方式和转正依据在提交/审核时验证；转正实习必须有招聘方留用原文。重复公司/岗位/城市/类型或来源相同会提示，不擅自覆盖合并。

后续 AI 提取必须附每个字段的原文证据，未知邮箱、链接、截止时间和留用承诺保持空值；人工修订与来源核验后仍须审核。Excel/CSV 批量导入先逐行校验和预览，全部进入草稿，不能直接发布。

## 端到端验收

1. 普通账号不能进后台、改角色、读草稿/原文或直接 REST/RPC 发布；伪造 user_metadata 的管理员角色仍无效。
2. 安全初始化首个超级管理员，第二次初始化拒绝；生成指定邮箱邀请，错误邮箱/过期/已领取/已撤销邀请拒绝，正确邮箱领取对应角色。
3. editor 上传真实文件、保存草稿，刷新及独立会话能读取，公开岗位广场与详情读不到草稿；保存原件、来源与投递信息关联到同一岗位。
4. editor 提交后不能自行批准或直接改状态；reviewer 核对来源、批准具体修订号，再发布；数据库真实落库且匿名前台能看到本条及正确的投递方式。
5. 修改已发布岗位需重新审核；过期批准、并发旧版本或跳过步骤均拒绝。下架/过期后前台和收藏/投递入口不再接受新操作，已有个人投递记录保留。
6. 审批、发布、权限变更都有不可由浏览器修改的日志；超级管理员停用账号后，该账号现有会话也不能继续操作；最后一个超级管理员不可被客户端停用或注销。
7. 桌面与手机检查真实表格、编辑、审核、权限、前台详情和持续导航；数据库测试与浏览器测试使用本机真实 Supabase，不触碰生产记录。
